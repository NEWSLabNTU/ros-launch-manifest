# T8. Predicate expressiveness

Exploration only; nothing decided. rlm at v0.3.14, play_launch at 8f29baad.

**Since v0.3.18 (rlm#7):** a predicate's value may be read from the launch
tree or a `let:` entry (`le: $(let v_odd)`), the practical half of the L4
island's per-class speed cap; evaluated per launch in SI units, unknown
(and unjudged) without a launch tree. The relational forms of section 5
(the value a field had at entry) stay out, as recommended below.
Probes: `play_launch/tmp/grammar-revision/T8-probe/` (YAML scalar style),
`play_launch/tmp/grammar-revision/T8-seq-probe/` (sequence read cost). Census:
`play_launch/tmp/grammar-revision/T7T8-census/out.txt`.

## 1. Issues (verified)

| # | Claim | Verdict | Evidence |
|---|---|---|---|
| E1 | A quoted upper-snake value is read as a constant, so `equals: "LAND"` on a `std_msgs/String` is refused | **Correct** | `parse_predicate_map` loads through `YamlLoader` (`types/src/parse.rs:191`), which drops scalar style; every `Yaml::String` goes to `PredicateValue::from_text` (`parse.rs:1674`), which classifies by shape only (`types/src/types.rs:765-775`). The resolver then refuses a constant the message does not declare (`resolve/src/ros/value_rules.rs:509-523`). |
| — | "serde_yaml does not keep style; the hand-written reader would read the event stream" | **Partly inaccurate, cheaper than stated** | The contract parser does not use serde_yaml; it uses yaml-rust2 0.9. Its event parser exposes the style, and rlm ALREADY walks that event stream for spans (`types/src/span.rs:77,128-205`). Probe output: `LAND` -> `Plain`, `"LAND"` -> `DoubleQuoted`, `'LAND'` -> `SingleQuoted`, `!!str LAND` -> `Plain` + tag `tag:yaml.org,2002:str`, block `>-` -> `Folded`. `YamlLoader` and serde_yaml_ng both lose it. |
| — | (new) Quoting ALREADY decides for bool and number | **New finding** | Probe: `equals: "true"` -> `String("true")`, `equals: true` -> `Boolean`, `"1"` -> `String("1")`. So method 1 extends a rule the parser already applies; it is not a new convention. YAML 1.2 §10.3.2 resolves every non-plain scalar to `!!str`; a schema may resolve PLAIN scalars further, which is exactly "plain upper-snake = constant". Spec-conformant. |
| T8-a | (new, serious) **A constant predicate is never judged at run time** | **New finding** | The model carries `{ constant: MANUAL }` without its value (`model/src/lib.rs:1190-1196`); `levels::eval` returns `None` for it (`play_launch/src/runtime_enforcement/levels.rs:72`, test at `:169-178` asserts it). For a value function `None` changes nothing (`mod.rs:1558-1561`), so the function is never lost by value: it reads as HELD. For `commands`, `!= Some(false)` skips it (`mod.rs:1600`), so `safe-state-violated` never fires. No warning. Affects 22 fixtures and the **island**: `driver_took_over: { of: [/vehicle/status/control_mode], when: { field: mode, not_equals: MANUAL } }` (`simple-autoware-safety-island/.../safety_island.contract.yaml:570-572`) is never evaluated. The resolver knows the value (`lookup_field` returns `constants` as `(name, value)`, `value_rules.rs:504-511`). |
| T8-b | (new) Value kind vs field type is not checked statically | **New finding** | `check_predicate_field` checks field existence, scalar-ness and constant names only (`value_rules.rs:502-558`). `equals: "MANUAL"` on a `uint8`, or `lt: 3` on a `string`... (ordering needs a number VALUE, `parse.rs:1690`, but the FIELD type is unchecked). At run time a mismatch is `None` (`levels.rs:52-70`): silently unjudged. This matters for either string method, because any change of meaning must fail loudly. |
| T8-c | Scalars only; no sequences in the interceptor | **Correct** | `resolve` returns `None` on `is_array_` (`play_launch_interception/src/fields.rs:128-130`); the resolver refuses a non-scalar field (`NotScalar`, `value_rules.rs:528-532`). Precedent: `tf.rs` walks `TFMessage.transforms` through `size_function`/`get_const_function`, capped at 1024 (`tf.rs:127`). |
| T8-d | No relational limit | **Correct, ruled** | `safety-functions.md` §7 decision 4; E1 gap U3 (results.md "Gaps found"). `PredicateValue` has no field-reference variant. |

Demand, measured: of the 12 E1 cases, ONE gap is a string-vs-constant
(U4), ZERO need a sequence, ONE (U3 continuous form) needs a relational
limit and was ruled out of scope. No predicate in the corpus names an index
or wildcard.

## 3. Methods: strings vs constants

| | Change | Size | Breaks | Migration | Risks |
|---|---|---|---|---|---|
| **S1** quoting decides (plain upper-snake = constant; quoted or `!!str` = string) | record value-scalar style in an event pass (extend `SpanReceiver`, or a 2nd receiver) and consult it in `parse_predicate_map`; `SpanIndex` paths do not include sequence indices (`span.rs:120-127`), so `commands` lists need an index segment | ~100 lines + tests | **nothing in the corpus** (0 quoted constants) | none needed | YAML calls style a presentation detail: a tool that re-emits contracts may change quoting (PyYAML/serde emit `MANUAL` plain, so low); invisible to a reader who does not know the rule; must honour explicit `!!str` |
| **S2** explicit key `{ constant: MODE_LAND }`, bare value always literal | parse a mapping value (~25 lines), field-table row, `migrate` rewrite plain upper-snake -> `{ constant: X }` (file-local, no `.msg` needed) | ~100 lines incl. migrate | **23 files** (22 fixtures + island) change meaning unless migrated; nano-ros's vendored copy too | mechanical `migrate` | without T8-b's type check, an unmigrated `equals: MANUAL` on a `uint8` becomes a string, never matches at run time, silently. | **S3** (new) both: S1's rule, plus S2's mapping accepted as the explicit form | S1 + S2 parse half, no migration | ~125 lines | nothing | none | two spellings for a constant (T3's "two forms" problem) |
| **S4** (new) resolve by the field's type: a `string` field compares a string, a numeric field a constant | needs the `.msg` at PARSE time; parser is layer-2 and must work without ROS (`when-field-unknown` already degrades to a warning there) | ~60 lines in the resolver | nothing | none | unresolvable without the ament index; ambiguity moves from syntax to environment |

## 4. Methods: sequences

Cost probe (Threadripper 7960X, release; per publish, reading one `float64`
from each element through C function pointers as `tf.rs` does):

| elements | reduce in-process to (min, max, len), one event | per element | one event per element, ring push only |
|---|---|---|---|
| 1 | 16 ns | 16.0 | 12 ns |
| 8 | 49 ns | 6.1 | 35 ns |
| 64 | 0.44 µs | 6.8 | 0.36 µs |
| 360 | 3.6 µs | 10.0 | 1.0 µs |
| 1081 (a LaserScan) | 8.4 µs | 7.8 | 2.4 µs |
| 4096 | 24.5 µs | 6.0 | 14.5 µs |

The per-element-event column omits the real per-event cost: phase 102 M0
measured ~50 ns per field event including the publisher lookup and the
locked ring push, so 1081 events is ~54 µs and 60 KB of ring per publish
(at 40 Hz, ~43k events/s from one topic, against a 65536-slot ring). The
in-process reduction is the only shape that scales: ~6-10 ns per element
plus one event. At 1081 elements and 40 Hz that is ~0.03% of a core.

| | Change | Size | Risks |
|---|---|---|---|
| **Q1** quantified path `wheels[*].speed` + `all`/`any` (grammar-revision method 3) | grammar: `[*]` in `field`, a quantifier key (a predicate has exactly one OPERATOR key, so the quantifier must be a separate key, e.g. `each: all\|any`); resolver: `.msg` lookup through `T[]`, `T[N]`, `T[<=N]`; interceptor: descend arrays, REDUCE in-process; model: path + quantifier | rlm ~80, resolver ~80, interceptor ~150, observer ~40 | **reduction by (min, max) answers `all` for every operator and `any` for ordering only**: `any equals c` / `all not_equals c` on numbers, and every string case, need the constant in the `.so` (a count of matches) or are refused. Primitive bool sequences have a NULL `get_const_function` in C++ introspection (Humble `msg__type_support.cpp.em:218`, `is_vector_bool`), so the reader must use `fetch_function`. Longer than the cap: report "unjudged", never truncate silently. One `[*]` only. |
| **Q1'** (new) push the predicate into the `.so` | the env list carries `op` and constant per line; the `.so` ships `(matches, len)` | +40 lines | moves constant resolution (T8-a) into the interceptor too; the `.so` starts evaluating contract semantics |
| **Q0** (new) stay out: a detector node publishes the verdict (`on: [reported]`) | none | 0 | the pattern rlm already prefers (a monitor is code, `fault-tolerance.md` §4.7); the sequence semantics stay in tested node code; costs a node |

## 5. Methods: relational

| | Change | Size | Risks |
|---|---|---|---|
| **R1** field on the right: `le: { field: limit, topic: /t }` (method 4) | parse a mapping value (collides with S2's `{ constant: }` mapping: keys distinguish); model: new untagged variant `Ref { topic, field }` (older readers fail to parse: schema bump); observer stores the latest value per declared field (today it evaluates on arrival and keeps nothing, `mod.rs:1547-1565`); static: the referenced topic must be declared with a type and the field must exist | rlm ~60, resolver ~60, observer ~60 | semantics to decide: a stale or silent reference (judge? unjudged? a fault?), time alignment (latest vs same stamp), rates; the referenced topic's omission becomes part of the hazard's detection and should be monitored |
| **R2** run-time rlx (method 5) | rlx evaluator in the observer on field values | large; rlx is a static evaluator (Z3 behind a feature) | puts an expression evaluator on the observer path; no case needs more than one comparison |
| **R0** stay out (decision 4) | none | 0 | U3's continuous form stays an extension's static check |

Prior art for R1: run-time assurance monitors (ASTM F3269) and STL monitors
(e.g. rtamt) compare signal with signal routinely; AUTOSAR E2E has no
relational check; ISO 13855 speed-and-separation is the canonical relational
safety function and U3 is it.

## 6. Recommendation

| Issue | Recommend | Why |
|---|---|---|
| T8-a constant never judged | **Fix first, independent of the grammar**: constant value in the model | It is a defect on a real system (the island's takeover function), silent and fail-unsafe (reads as held). |
| T8-b type unchecked | **Add the kind/type rule** before changing string semantics | Makes every meaning change loud, whichever string method wins. |
| E1 strings | **S1 (quoting decides)**, which the phase 102 evaluation already ruled (results.md, E1 gap row: "a quoted YAML scalar is a string. rlm, next release") | Zero breakage in the corpus (0 quoted constants), no migration, consistent with how quoting already decides bool and number, spec-conformant, and the event-stream machinery exists. S2 is the fallback if a reviewer rejects style-dependence; then migrate the 23 files mechanically. |
| Sequences | **Q0 now**; Q1 with in-process (min, max) reduction and a refused-not-truncated length cap only when a case needs it | No E1 case and no corpus contract needs one; the cost is fine but the semantics (any/equals, bool vectors, caps) add surface for no current user. |
| Relational | **R0 now**; R1 when a case needs it, after deciding staleness and alignment | One ruled gap; R1's run-time cost is trivial, its semantics are not. |

## 7. Contradictions with grammar-revision.md

- Its leaning for strings is **S2**; play_launch's evaluation already ruled
  **S1** (results.md E1). The S2 reason ("does not depend on the YAML
  library") is weaker than stated: the library in use exposes style, rlm
  already reads its event stream, and quoting already changes bool/number.
- "serde_yaml does not": the contract parser uses yaml-rust2, not serde_yaml.
- It omits T8-a and T8-b, which are defects, not expressiveness.
- Its sequence leaning (method 3 with a length bound) is sound on cost, but
  must name the reduction: per-element events do not scale, and min/max
  covers only part of `any`.

## 8. Open questions

1. Style-dependent meaning (S1) acceptable for a safety contract, or must
   the meaning be visible without knowing YAML's quoting rule (S2/S3)?
2. Should the constant's numeric value also be printed in `--explain` and
   messages (`MANUAL (4)`)?
3. Sequences: is a detector node (Q0) the intended pattern, to be written in
   the guide, or a gap to close?
4. Relational: if adopted, is a silent reference topic a fault of the
   predicate (strictest) or unjudged?
5. Does a predicate on a `wstring` hash the same way (UTF-16 bytes)? The
   interceptor's `16` type id covers `string` only; `wstring` (17) is
   refused by `value_kind`, which the type rule (T8-b) should mirror.
