# T6. Naming consistency

Exploration for `ros-launch-manifest/docs/design/grammar-revision.md` T6, against rlm
v0.3.14, play_launch `8f29baad`, nano-ros-pl `b7f7bae4c9`, island `addcefd`. Nothing here
is decided.

`ft` = `rlm/types/src/field_table.rs`, `parse` = `rlm/types/src/parse.rs`. Counts: 192
contract files (rlm 35, play_launch 123, nano-ros 33, island 1), YAML walk
(`T5-probe/count_keys.py`). Probes: `T6-probe/` (`cargo run` and `cargo run --bin
quantity` against the rlm path crates; `scan_table.py`).

| Near-miss `tolerance` / `tolerate` | **Confirmed**, small: `tolerance` 3 writes (rlm 2 on node paths, pl 1 on a chain), `tolerate` 2 (pl). Goes with T2. |

Probe output (`T6-probe`, `parse_manifest_str`):

```
min_rate_hz: 100                -> OK
min_rate_hz: 100Hz              -> ERR expected a number, got a quoted string — remove the quotes ...
min_rate_hz: "$(param rate) Hz" -> OK
timer.rate_hz: 100Hz            -> ERR at 'nodes.a.paths.p.rate_hz': expected a number, got a quoted string ...
min_rate: 100Hz                 -> ERR unknown key ... did you mean `min_rate_hz`?
max_latency: 10                 -> ERR `max_latency: 10` has no unit — write `max_latency: 10ms` ...
```

rlx's quantity parser (`rlx/src/value.rs:110`, `Env::parse_quantity`, already a dependency
of `types`) against `Frequency`:

```
100Hz -> 100.0   100 Hz -> 100.0   0.1 kHz -> 100.0
100   -> ERR `100` needs a unit: a Frequency, e.g. `100 Hz`
10ms  -> ERR `10ms` is a Time, but a Frequency is expected
1/10ms, 100 1/s, 6000 / min, 100 rpm -> ERR not a value
```

So a unit-valued rate is a reuse, not new code; and a period written where a rate belongs
is refused by dimension, which closes method 2's inversion risk for free under method 1.
Units available: `Hz`, `kHz` only (`rlx/src/units.rs:91-92`).

Model field names carry units by design (`max_latency_ms`, `min_rate_hz`, `rate_hz`) and
are independent of the contract's spelling (the contract dropped `_ms` in phase 70; the
model kept `_ms`). So **a contract-only rename does not change the model**, and nano-ros's
cost is: the tag bump, its 44 rate writes in 33 contracts, `entity_census.rs` strings, and
— only if rlm's struct fields are renamed — one pattern match.

## Methods

### Method 1 — rename with the schedule (`event_chains:`; `min_rate: 100Hz` …)

| Aspect | Assessment |
|---|---|
| Change (rates) | 5 keys → `min_rate`, `max_rate`, `rate` (topic), `trigger.timer.rate`, `arrival_curve.rate`; value parsed by `rlx::Env::parse_quantity(…, FREQUENCY)` (bare number refused as for durations); old keys `deprecated` alias rows at R, `removed` at R+1 |
| Change (`paths:`) | root and `includes.<i>` / `overrides` `paths:` → `event_chains:`; node `paths` unchanged |
| Model | unchanged (keep `scope_paths`, `*_rate_hz`), or rename `scope_paths` → `event_chains` in a schema bump (nano-ros 4 files, play_launch runtime 6 files; `SystemModel::from_yaml_str` already rewrites old field names on read) |
| Size | rlm: ~10 field rows, parse (`yaml_rate_bound`, `yaml_rate_at`, timer, topic, arrival curve), `bound.rs` BOUND_KEYS units, `migrate` (~150 lines: key rename + `N` → `N Hz`; precedent: `entry_speed: <n>` → `<n> m/s`, `migrate.rs:117`), `rule_names::RENAMED_KEYS`; play_launch: diagnostic strings (backticked `rate_hz`/`min_rate_hz` mentions: rlm 46+35, pl 34+31) |
| Writes rewritten | 470 rate values, 115 `paths:` sections |
| Migration | Fully mechanical. `$(param x) Hz` values keep their text. Map form `rate_hz: { value, source }` (2 writes) keeps its shape |
| nano-ros | tag bump + `migrate` over 33 contracts (44 values) + `entity_census.rs` strings + inline test YAML; struct-field rename optional |
| Risk | Two releases with both spellings; `min_rate` and the extension key `hazard.min_rate : Flow` in `reference/occlusion.rlx` share a name in different contexts (no clash: extension keys are hazard/settle only) |

### Method 2 — periods instead of rates (`min_period: 10ms`)

Durations are the majority value type and the parser exists. But: ROS practice is rates
(`ros2 topic hz`, Nav2 `controller_frequency`, Autoware `update_rate` parameters — and the 24
`$(param …) Hz` references read exactly those parameters); `rclcpp` timers and the DDS
`deadline` QoS take periods, AADL uses `Period` (AS5506 Timing_Properties). An upper rate
bound becomes a lower period bound (`max_rate_hz` → `min_period`), so every comparison in
the rate rules (`rate-hierarchy`, `derivable-min-rate`, `queue-drain-rate`) inverts, and
every `$(param rate) Hz` would need `1 / $(param rate) Hz`, which `values::parse_expr` does
support (`/` is an operator). Same write count as method 1, plus rule rewrites; higher risk.

### Method 3 — accept a rate or a period in one key

`min_rate: 10ms` read as 100 Hz. Two spellings for one fact (the condition
`standard-names.md` exists to remove), and a `10ms` meant as a typo for `10Hz` would parse.
The dimension refusal in the probe is a feature method 3 throws away.

### Method 4 — gate the field table's prose

Make `check_terms.py` scan `ft` rows whose status is `Live` (or `Deprecated`), skipping
`removed` rows, and drop `field_table.rs`/`format-reference.md` from `ALLOWED_FILES` (or
scan only the generated reference's live sections). Probe (`T6-probe/scan_table.py`, the
current `RETIRED` list over 243 rows: 216 live, 3 deprecated, 24 removed): **1 hit**, the
live `trigger` row (`spontaneous`). Cost: ~30 lines in the script, one self-test case.
Note it only catches words already on the `RETIRED` list; method 1's renames must add their
old spellings there at R+2, as phase 98 did. Alternative home: a `#[test]` in `field_table`
iterating `FIELDS`, so `cargo test` gates it without Python — but the word list lives in
Python today (`types/tests/retired_terms.rs` runs the script).

### Method 5 (added) — fix the literal-unit refusal now

Independent of any rename: route a non-numeric scalar under a rate key through
`Env::parse_quantity`, accepting `100Hz` beside `100` (both meaning 100 Hz) for one release,
or at least make the message say "write the number in Hz without a unit" instead of
"remove the quotes". Cost: ~20 lines. Downside if acceptance is chosen: a second spelling
under the old name, which method 1 then has to retire too; the message fix alone has none.
