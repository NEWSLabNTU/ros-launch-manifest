# T4. Domain and platform content in the core

Exploration for `ros-launch-manifest/docs/design/grammar-revision.md` T4, against
rlm v0.3.14 and play_launch `8f29baad`. Nothing here is decided.

Abbreviations: `ft` = `rlm/types/src/field_table.rs`, `parse` = `rlm/types/src/parse.rs`,
`sup` = `play_launch/src/ros-launch-resolve/resolve/src/ros/supervision.rs`,
`ext` = the same directory's `extensions.rs`.

## Issues (verified)

| # | Issue as stated | Verdict and evidence |
|---|---|---|
| 1a | `safe_state.settle.response` is a vehicle concept | **Wording only.** The doc says "the vehicle's response: from the braking command to the deceleration" (`ft:1463-1466`), but the key is a generic actuation delay: the consumer adds it to a WRITTEN duration too (`ft:1371`), and only 1 of 7 extensions reads it (`vehicle.braking.rlx:16`). The others name their own actuation time (`iso13855 hazard.device_response`, `ebd settle.traction_cut_off`/`brake_build_up`, `pst settle.valve_stroke`). IEC 62061 / ISO 13849 call the same span the final element's part of the "safety function response time". |
| 1b | `supervise.early: { within, drop }`, `drop` a speed | **Confirmed, and deeper than stated.** `drop` is parsed by a private speed parser that knows only `m/s` and `km/h` (`parse:1146-1155`, not the rlx unit table); its doc says "the least speed the vehicle must have shed" (`ft:1673-1676`). The static check is core Rust (`sup:997-1097`, `early_fit`, rule `supervised-early`); only the physics (`derive settle.speed_lost`) is rlx. |
| 1c | `supervise.observes` worded as seeing standstill | **Confirmed, and it is semantics, not wording.** `ft:1610-1613` and `sup:220-300` ("how late standstill is seen"). The model lowers `observes: <node>/<sub>` with no field (`model/src/lib.rs:1584-1604`), so "standstill" and "speed" are never stated: a runtime must know by convention which field of the observed message is the speed. The island does: `ISLAND_SUPERVISOR_EMERGENCY_DROP_MM_S` etc. are transcribed into Kconfig by hand (`safety_island.contract.yaml:805-829`). |
| 2 | `supervision: { tick, switch }` are platform facts | **Confirmed.** Read only by `sup:421-479` (`platform()`, `detection()`), never lowered to the model, never read by any runtime (play_launch `src/play_launch/src`, interceptor, nano-ros: 0 reads). A contract shared by a Linux and a Zephyr image can state one tick only. AADL puts the same facts on the processor (`Thread_Swap_Execution_Time`, `Clock_Period`, `Scheduler_Quantum` apply to processor components, AS5506 Timing_Properties); AUTOSAR WdgM's supervision cycle (`WdgMSupervisionCycle`) is ECU configuration, not SWC description. |
| 3 | `policy.unsupervised_measured` is tool policy | **Confirmed, and unused.** Severity selector for `measured-unsupervised` (`ft:1781-1784`, `sup:1118-1136`). **0 contracts write `policy:`**; the only writer is one inline test (`play_launch/tests/tests/manifest_check.rs:3799`) plus rlm parse tests. |
| — | "Method 1 is an rlx language change (0.2.0 -> 0.3.0); it needs the prover to cover the new context" | **Overstated.** rlx has no list of key contexts: `key supervise.drop : Velocity` and `key foo.speed : Velocity` both pass `rlx check` today (probe `T4-probe/sup.rlx`, `ctx.rlx`). The restriction to `hazard.`/`settle.` lives in the CONSUMER: `parse:330-333` (`extensible()`), and `ext:1101-1214` (`validate_keys` only loops hazards and settles). The prover is context-free (keys are SI reals): `rlx prove` on a `check early_drop_nominal: drop <= shed(within - response, decel, jerk)` with `worst_case: increasing in drop` returned **proved**. rlx needs a change only if a NEW core input (`CORE_INPUTS`, `typeck.rs:73`) or derive target (`DERIVE_TARGETS`, `typeck.rs:82`) is wanted. |

How the early check works today (vehicle.braking 1.1.0 + rlm v0.3.1): the parser reads
`early: { within, drop }` into `EarlyCheck { within, drop_mps, drop_text }` (`parse:1085-1143`);
`sup::early_fit` errors if `within <= response` or `within >= settle`, then calls
`ext::derived_speed_lost` (`ext:2204-2262`), which evaluates the extension's
`derive settle.speed_lost` with the core input `elapsed` bound to `within`
(`elapsed` is readable only by that derive, `typeck.rs:70-76`); `drop > speed_lost` is an
error, `<=` an info, no derive a warning. The lowered model field
`EarlyCheckContract { within_ms, drop_mps }` (`model/src/lib.rs:1612-1617`) has no reader
anywhere (play_launch runtime 0, nano-ros 0).

## Methods

### Method 1 — a `supervise.` extension context, `drop` into `vehicle.braking` 1.2

What it actually needs (probe-checked):

| Layer | Change | Size |
|---|---|---|
| rlx | **None required.** `key supervise.drop : Velocity` and `input supervise.within : Time` type-check; a `check` over them is proved. Optional: a typeck rule like `ELAPSED_READERS` that keeps `supervise.*` inputs out of hazard-wide checks | 0 – 40 lines |
| types | `extensible()` gains `Context::SuperviseEarly` (`parse:331`); `parse_early` stops requiring `drop` and collects extension keys like `extension_keys` (`parse:393`); `EarlyCheck.drop_mps` becomes `ext: Vec<ExtKey>`; field-table row `drop` (`ft:1673`) removed | ~80 lines |
| consumer | `validate_keys` loops supervised settles with context `supervise`; `gather` binds `supervise.within` and reads `supervise.*` keys from the settle; `run_checks` gets a per-supervised-settle pass (today checks run per hazard, `ext:2292`); a severity rule for such checks (today a check is an error only when a hazard's `deadline_by` names it — the early check is an error now and must stay one); `early_fit` keeps only the two ordering errors | ~200 lines, -60 |
| extension | `vehicle.braking` 1.2.0: `key supervise.drop : Velocity`, `input supervise.within : Time`, `check early_drop_nominal: drop <= shed(within - response, decel, jerk)` with a proved `worst_case` | ~10 lines |
| model | `EarlyCheckContract.drop_mps` either keeps its name (filled from the extension key — the model then names a vehicle concept again) or becomes generic; no reader exists, so either is free for nano-ros | small |
| contracts | **No text change.** The island writes `early: { within: 1319ms, drop: 0.25 m/s }` under `use: { vehicle.braking: "^1" }`; `^1` accepts 1.2.0 and `drop` stays where it is | 0 |

Breakage: a contract with `early.drop` and no `use:` of an extension declaring it (0 today).
Migration: none needed. Risk: **the runtime half is not moved.** The check the platform
runs ("the vehicle has shed at least `drop` since arming, or is at standstill") is
evaluated on the target, and the target never runs rlx (`docs/extension-guide.md`, "What
leaves the checker"). After method 1 the core still has to tell a runtime WHAT to measure
and compare, and that is still a speed. Method 1 relocates the static check and the word,
not the semantics.

### Method 2 — generalise the wording, keys stay core

Rewrite `ft:1466` (`response`: "the actuation delay: from the safe state's command to the
plant's first response"), `ft:1478`/`ft:1613` (`observes`: "the input the safe state is
seen on"). Cost: text only, regenerate `format-reference.md`; no parse, model or nano-ros
change. Fits `response` (issue 1a is wording). Does not fit `observes` (issue 1c is a
missing field, not a word) or `drop` (a speed by type).

### Method 3 — `supervision` into the platform file

Add a target-independent `supervision: { tick, switch }` to `PlatformFile`
(`sched/src/platform.rs:251-262`; today `resources` is typed only for `posix`, raw for
any other target, `:206-210`). Consumer: resolve the platform file before
`load_manifests` and carry the facts in `ContractSources` (precedent: `lock`,
`process_per_composable`, `manifest_loader.rs:52-64`), because the overrun rows are built
inside `load_manifests` (`manifest_loader.rs:4244`) while `check` resolves the platform
file only after it (`verbs/check.rs:248-286`). Alternatively recompute the rows after
loading, as `period_range::with_platform_budgets` already patches budgets (`check.rs:280`).

| Aspect | Assessment |
|---|---|
| Size | ~150 lines play_launch (plumbing + 5 call sites of `load_manifests`), ~40 lines rlm sched |
| Breakage | 5 contracts (pl 4, island 1) move 2 lines each; the island needs a platform file for a `zephyr` target, which it does not have today |
| Migration | `migrate` cannot write a second file per contract it rewrites; a refusal naming the destination, plus a one-off script, is the realistic path |
| Without a platform file | `detection()` already returns "unknown", so supervised budgets read incomplete, not wrong (`sup:441`) |
| nano-ros | 0 readers; it states tick per board in `system.toml`, which is where this belongs |
| Risk | `check` on a contract alone no longer proves a supervised budget fits; fine for review, but CI must pass `--sched` |

### Method 4 — `policy` into tool configuration

Options: (a) a project file beside `rlm.lock`; (b) a flag. A one-rule key is a poor shape
for either; the better form is a generic per-rule severity flag
(`check --deny measured-unsupervised`, as clippy's `-D <lint>` / `[lints]` in `Cargo.toml`
keep project-wide severity out of the source). Breakage: 0 contracts. Cost: parse row
becomes `removed` with a message naming the flag; `sup:1118` reads the flag. ~40 lines.
Tension to record: `acknowledged:` is also tool policy in the contract, but per finding,
and it is evidence a reviewer reads; `policy:` is not.

### Method 5 (added) — make `early` and `observes` domain-free in the core

Instead of moving `drop` out, state what the runtime measures, in core terms the target
can evaluate without rlx:

```yaml
supervise:
  observes: { input: mrm_handler/kinematic_state,
              field: twist.twist.linear.x,          # what is observed
              reached: { le: 0.01 } }               # the safe state, a `when:` predicate
  early: { within: 1319ms, decrease: 0.25 m/s }     # least change of `field` since arming
```

`field` and `reached` reuse the `when:` predicate grammar (`ft:1396-1440`: `field`, `lt`,
`le`, `ge`, `equals`, ...) and the interceptor's field reader (phase 102 M0b); the value
is SI by ROS convention (REP 103), so `decrease` takes any rlx unit of the field's
dimension. The extension's static check (method 1) can still read `early.decrease` as an
input. Cost: grammar + model fields (`observes_field`, `reached`, `decrease_si`),
~150 lines rlm, ~100 play_launch; the island contract gains `field`/`reached`; runtime
readers: none yet, so no nano-ros code. Risk: `abs()` of a velocity (reversing) is not a
scalar predicate; needs T8's expressiveness if a signed field must be compared by magnitude.

## Recommendation

| Issue | Method | Why |
|---|---|---|
| `response` | **2** | It is generic already (written-duration path, IEC 62061/ISO 13849 usage); only the doc is vehicular. |
| `drop` | **1 for the static check, 5 for the runtime contract** | 1 alone leaves the target reading a speed by convention; 5 alone leaves the nominal-profile check in core Rust. Together: core states the observable and the change, the extension proves the change is nominal. 1 costs no contract edits. |
| `observes` | **5** (`field` + `reached`) | The defect is the missing field, not the word. |
| `supervision` | **3**, with a target-independent section | Platform-varying, read by nothing but one checker function. |
| `policy` | **4**, as a generic per-rule severity flag | 0 contracts use it. |

Ordering: 2 and 4 are free and independent; 3 needs the `ContractSources` plumbing; 1 and
5 should land together with `vehicle.braking` 1.2.0.

## Open questions

1. Should the island get a zephyr platform file at all, or should `supervision` sit in a
   target-independent file? (nano-ros keeps per-board facts in `system.toml`.)
2. Severity of an extension `check` in the `supervise.` context: always an error (as
   `supervised-early` is), or only when named, as `deadline_by` does for hazard checks?
3. Is `EarlyCheckContract.drop_mps` kept as a name (a vehicle word in the model) or made
   generic now, while it has no reader?
4. Method 5 makes `observes` a map; keep the string form as shorthand (T3's desugar), or
   one form?
5. Does `--deny <rule>` generalise far enough to retire `--strict`'s special cases, or
   stay a separate mechanism?
