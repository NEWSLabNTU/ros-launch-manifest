# T3. Two forms for one structure

Trees as in T1.md. Probes: `play_launch/tmp/grammar-revision/t3_desugar.py`,
`T3-probe/{two,self}/<fixture>/{orig,desugar}/`, `T3-probe/report_*.json`.

## 1. Issues, verified

### 1a. `hazards.<h>.reaction` (event chain) vs `enters` (mode)

**Verified: one structure, two spellings — and the code already treats the
chain form as a one-level ladder almost everywhere.**

- Grammar: exactly one of the two (`field_table.rs:1222-1232`; parser
  refuses both, fixture `contract_enters_and_reaction`).
- The model already has ONE field: `HazardContract.reaction`, "a key into
  `modes` … else a key into `scope_paths` … a reader resolves it … a mode
  first" (`model/src/lib.rs:1272-1278`). Written from
  `HazardDecl::entry()` (`types.rs:903-905`; `causal_graph.rs:558`).
- The checker's ladder: `resolve_ladder` returns a one-rung ladder
  `[(chain, chain)]` for the chain form (`manifest_loader.rs:3285-3295`), and
  walks the mode's `fallback:` otherwise. Every per-level rule
  (`fault-reaction-time`, `degradation-level-time`, settle, calls) runs on
  that ladder.

**But "a reaction" means four different things for a mode, depending on the
reader** — which decides what a desugared implicit mode must look like:

| Reader | What a mode-form hazard reacts by | Where |
|---|---|---|
| play_launch checker (`resolve_ladder`) | the entered mode's `fallback:` levels, each level's own `reaction:`; the entered mode's own `reaction:` is ignored | `manifest_loader.rs:3297-3330` |
| play_launch runtime observer, `measure` | the LAST fallback level's `reaction:` (`terminal_reaction_path`) | `runtime_enforcement/view.rs:169-179`, `commands/measure.rs:114` |
| play_launch `supervise.enters` | the entered mode's OWN `reaction:` | `supervision.rs:380-395` |
| nano-ros `ftti_budget::reaction_path` (and its observer rows) | the entered mode's OWN `reaction:`; none → "entering it IS the reaction" | `nano-ros-pl/.../nros-orchestration-ir/src/ftti_budget.rs:391-402` |
| play_launch criticality derivation ("reacts") | **chain form only**; `enters:` credits no reacting node | `manifest_loader.rs:5232-5248` ("`enters:` names a mode and is never read as a path") |

The last row is a real divergence between the two forms today (§3). The
middle rows disagree with the checker for any mode whose own `reaction:`
differs from its last level's — an existing inconsistency independent of T3,
but one a desugaring must not widen.

### 1b. `services.<s>.max_transport` vs `links:`

**Verified.** `services.<s>.max_transport` (v0.2.5, `SINCE`
`field_table.rs:2039`; row `:856-859`) is the request leg's transport "for
every client … that states none of its own" — the topic-level-default shape
G3 deprecated for topics (`field_table.rs:780-785`). Readers:
`model_builder.rs:463` (a client inherits it), `manifest_loader.rs:437-438`,
`:1455` (budget sources), `:7022` (merge). `cli.<e>.max_transport` exists,
`cli.<e>.link` does not (links are subscriber-only, `field_table.rs:602`).
Only the request leg is modelled; a link for a call would need to say which
leg (or both).

### 1c. `integrity_levels:` vs a profile

**Verified, and fully redundant in the corpus.** A contract may not have both
(`integrity-scale-conflict`, `extensions.rs:641-651`). Without a profile,
`integrity_scale()` uses `integrity_levels:` with the "thirds" map
`criticality_of` (`types/src/integrity.rs:30-40`); with one, the profile's
explicit map (`extensions.rs:196-203`). For 5-level scales the thirds map
gives `—, low, medium, high, high`, **identical** to both bundled profiles'
maps (`types/profiles/iso26262.profile.yaml:8-9`,
`iec61508.profile.yaml:6-7`).

## 3. Probe: desugaring the chain form, fixture by fixture

`t3_desugar.py` rewrites every chain-form hazard in every play_launch fixture
into the mode form, runs `check` and `resolve` on the original and the
rewrite (both round-tripped through one YAML dumper; locations stripped),
and diffs. Two shapes:

- `two`: `enters: H__r`; `H__r: { fallback: [H__lvl] }`, `H__lvl: { reaction: X }`
- `self`: `enters: H__r`; `H__r: { fallback: [H__r], reaction: X }` — the
  only shape all four readers in §1a resolve to `X`.

Results (both shapes identical; 38 fixture files, 43 hazards; the
`contract_enters_and_reaction` refusal fixture excluded as not applicable):

| Compared | Same | Different |
|---|---|---|
| exit code of `check` | 37/37 | 0 |
| multiset of `severity[rule-id]` | 36/37 | 1: `contract_criticality_written` loses `error[derivable-criticality]` |
| model, per hazard: `ftti_ms` + every degradation level's `(role, route_ms)` | 18/18 resolvable | 0 |
| model, `execution.tasks` (the schedule) | 18/18 | 0 |
| model, `contracts.node_criticality` | 3/18 | **15/18**: every node on the reaction route loses its derived integrity (e.g. `contract_fault`: `/safety/brake_controller: high` disappears) |
| text | 3/37 | 34: wording only — `reaction-unguarded` says "enters mode 'H__r', whose reaction ends at …" for "reaction 'X' ends at …"; diagnostic paths `hazards.h.reaction` → `.enters`; level names in `settle-derived`/`call-unbounded-mrc` |
| `self`-fallback | accepted by the checker (no cycle refusal) | — |

Reading: **the arithmetic is already form-independent**; the one semantic
difference is the criticality derivation's chain-only reacts leg
(`manifest_loader.rs:5232-5248`). That is a defect in the mode form today,
not a property of the chain form: a hazard in the island or rt_av_demo
style credits no integrity to its reacting nodes. Fixing it (walk the ladder
from `resolve_ladder` there too) would make the desugaring
model-identical except for names.

## 4. Methods

| # | Method | Change | Size | Breaks | Migration | Risks |
|---|---|---|---|---|---|---|
| 1 | Desugar in the parser (implicit mode) | Parser turns `reaction: X` into `enters: <h>.reaction` + an implicit mode (the `self` shape); a flag keeps it out of the model's `modes`, of runtime `mode-availability`, and keeps diagnostic wording/paths on `reaction` | rlm ~80 lines; play_launch: criticality fix (~20) + a "synthetic" flag honoured by `reaction-unguarded`, `hazard_sentence`, `acknowledged:` paths (`acknowledge.rs:575-582` match `hazards.h.reaction`) | Nothing user-visible if the flag is honoured; without it, 34 fixtures' expected text and every `acknowledged:` entry at `hazards.<h>.reaction` | none | Leaky: every consumer of `modes` must learn to skip synthetic ones; a model reader (nano-ros) would see the implicit mode unless filtered; the probe shows the names DO leak into 34 outputs without it |
| 1′ (new) | **Unify at the rule level, not the grammar** | Keep both keys and the model's single `reaction` field; route every rule through `resolve_ladder` (already one-rung for chains). Concretely: the criticality reacts leg; and pick one meaning of "a mode reacts by" for `terminal_reaction_path`, `supervision.rs`, nano-ros `reaction_path` | play_launch ~40 lines + a nano-ros note | `contract_criticality_written` and every mode-form fixture's `node_criticality` (they GAIN reactors — the fix) | none | Leaves two spellings, which is what T3 set out to remove; but the "one path in the code" goal of method 1 is reached with no synthetic objects |
| 2 | Remove the short form | `reaction:` on a hazard becomes a `removed` row; `migrate` writes the `two` shape (or `self`) | rlm ~60, `migrate` ~80; 39 fixture files rewritten | 39 play_launch fixtures; any external chain-form contract | mechanical (the probe's rewriter is one) | The simplest case gets 2-4 lines longer; also collides with T1 (the deprecated `reaction: <mode>` must finish R+1 first, else one key has three meanings across releases) |
| 3 | Scale as an inline/anonymous profile | (a) `integrity_levels:` becomes an anonymous profile internally (behaviour already identical); or (b) removed, `migrate` writes `use: iso26262` / `use: iec61508` (exact match) or a local `.profile.yaml` | (a) ~30; (b) ~50 + a profile-file writer | (b) 23 fixtures | (b) exact for all 23 corpus uses; a custom scale needs a written profile file | (b) adds `use:` lines, which `rlm.lock` then records; 22 of 23 uses equal the DEFAULT scale and could simply be deleted |
| 4 | Services take links | `cli.<e>.link` (and `srv.<e>.link`?) naming a `links:` entry; `services.<s>.max_transport` deprecated on the §6 schedule | rlm ~60, play_launch ~40 (budget sources, merge) | nothing in the corpus (0 uses of the service key) | `migrate`: copy onto each client in the file (same partial-coverage problem as the topic key, T1) | The link must say which leg; today only the request leg exists, so a link on a client is the request hop and the response hop stays unbounded |

Prior art. AADL EMV2 and ISO 26262 both state the reaction as a transition
to a *state/mode* (EMV2 error-event-triggered mode transitions; ISO 26262-1
defines "safe state" and "emergency operation" as operating modes); neither has a second,
mode-less spelling, which argues that the mode is the primitive and the
chain the sugar. AUTOSAR PHM/WdgM likewise hand a supervision failure to a configured
recovery action rather than to a free route.

## 5. Recommendation

- **Reaction**: **method 1′ now** (fix the criticality reacts leg and settle
  one meaning of "a mode reacts by" across play_launch and nano-ros); that
  removes the only measured semantic difference between the forms and gives
  the code one path. **Then method 1 (parser desugar) is cheap but not
  needed**: the model already has one field, and the remaining differences
  are names. Choose between keeping the shorthand (doc's leaning) and
  method 2 on readability alone — the probe shows nothing else depends on it.
  If desugaring, use the `self` shape: it is the only one every current
  reader resolves correctly.
- **Services**: method 4, but on the R schedule **with zero corpus uses**,
  this is the cheapest moment; specify the leg first.
- **Scale**: method 3(b) is lossless for every corpus use (22 → delete or
  `use: iso26262`, 1 → `use: iec61508`); 3(a) if a custom scale without a
  file must stay expressible.

## 6. Open questions

1. What does entering a mode run: its own `reaction:`, its first level's, or
   its last level's? Three answers exist in code today (§1a). This must be
   decided before any desugaring; the checker's answer (walk `fallback:`,
   ignore the entered mode's own `reaction:`) is the arithmetic one.
2. Is the criticality reacts leg's chain-only reading a bug (credit every
   level's route) or intended (credit only the MRC route)? The probe shows
   15/18 models change either way.
3. For a desugared or migrated hazard, which name do diagnostics and
   `acknowledged:` paths use — the hazard's `reaction` or the implicit mode?
4. Service links: one link per call (both legs) or per leg? Does a
   response-leg transport belong in the grammar at all (`max_response`
   already bounds the server)?
5. `integrity_levels:` with a scale no bundled profile has: keep the key as
   an inline anonymous profile, or require a local profile file?
